# 貓空纜車調度系統

貓空纜車車廂即時調度管理工具。以 Next.js + Supabase 建置，支援多人即時同步、拖曳排班、維修標記等功能。

**線上網址：** https://maokong-dispatch.vercel.app

---

## 系統架構

| 層次 | 技術 |
|------|------|
| 前端框架 | Next.js 16 (App Router) |
| 資料庫 | Supabase (PostgreSQL + Realtime) |
| 部署 | Vercel |
| 樣式 | Tailwind CSS + shadcn/ui |
| 拖曳 | dnd-kit |

---

## 帳號與權限

| 角色 | 功能 |
|------|------|
| admin | 完整操作（拖曳、修改、設定、診斷） |
| guest | 唯讀（看即時狀態、搜尋） |

帳號由 admin 在系統設定 → 帳號管理新增。登入後右上角顯示目前角色與帳號 email。

## 車廂種類與狀態

### 車廂種類

| 車號 | 類型 | 說明 |
|------|------|------|
| 1–147 | regular | 一般車廂 |
| M1、M2 | maintenance_vehicle | 維修車 |
| 雙握 | shuangwo | 雙握車（固定 1 台）|
| 洞 | dong | 洞車（固定 1 台）|

全系統共 **151 台**車廂（1–147 + M1 + M2 + 雙握 + 洞）。

### 車廂狀態與顏色

| 顏色 | 狀態 | 說明 |
|------|------|------|
| 藍色 | 可用（一般車） | 正常運行 |
| 黃色 | 可用（水晶車） | 特殊車型，由設定指定 |
| 灰色 | M1/M2/雙握/洞 | 固定特殊車廂 |
| 紅色 | 不可用 | 暫時停駛 |
| 黑色 | 報廢 | 封鎖上正線，集中停用區顯示 |
| 橘色 | 管控 | 特別管控狀態 |
| 紫色 | 有維修需求 | 由維修排程區登錄後自動驅動 |
| 綠色 | 其他 | 自定義用途 |

狀態顏色（除雙握、洞外）可在系統設定自訂。

## 功能總覽

### 頂部工具列（TopBar）

#### 搜尋車號
在頂列輸入框輸入車號，按 Enter 或「搜尋」鍵查詢：
- 顯示該車目前所在區域與格位（正線顯示第幾格）
- 若有維修需求一併標示 ⚠
- 搜尋命中後，目標車廂標籤立即套用紅色閃爍外框（v1.1 新增），持續顯示直到清空搜尋框
- 正線格位以 `mainLine.positions.indexOf()` 直接查詢，不依賴可能過時的 `location_slot` 欄位（v1.4 改善）

#### 車廂備註全覽（📋 N 按鈕）（v1.4 新增）
頂列 📋 按鈕旁顯示橘色數字（N = 有備註車廂數）：
- 點開後以 Modal 列出所有有備註車廂的 ID、所在位置與備註內容
- Admin 可直接點 🗑 從 Modal 刪除任一筆備註

#### 班次快照（💾 儲存班次）（Admin 限定）
點擊後輸入班次說明，系統記錄當下完整狀態，包含正線排列、各區車廂（含備註）、自定義區（含備註）、維修排程、週排程。**佈告欄不納入快照**（交接內容應由控制員手動維護）。

#### 班次記錄（📂 記錄）（v1.9 新增，Admin 限定）
點擊後從右側滑出班次記錄 Panel，顯示最近 30 筆快照（依台北日期分組，最新在上）：
- **儲存當前狀態**（v1.12 新增）：Panel 頂部輸入名稱後點「儲存」，立即建立手動快照並存入 Supabase `snapshots` 表，儲存後清單自動更新
- 每筆顯示：班次說明、時間、操作者、正線模式與已排台數
- **預覽**：展開摘要，含轉角二站/貓空站台數、維修排程人數、報廢車數
- **還原**：需輸入登入密碼驗證身份，確認後覆蓋正線、車廂、自定義區、維修排程、週排程，完成後自動重新載入；佈告欄不還原

#### 匯出功能（v1.12 新增）

| 按鈕 | 說明 |
|------|------|
| 📊 Excel | 下載 `.xlsx`，含 5 個工作表：正線排列、車廂狀態、自定義區、維修排程、週排程，檔名自動帶台北時間 |
| 📷 截圖 | 擷取整個調度畫面（含左右儲車區、正線迴圈、中央面板），存為 2× 解析度 `.png`；圖片右下角自動疊加截圖當下的台北時間（格式：`📷 2026/05/31 17:30:25`），截完畫面不留痕跡 |

### 正線迴圈

#### 模式切換
支援 **108 車** 與 **130 車** 兩種模式：
- 左上方按鈕切換，Admin 限定
- 108 模式格子較大（約 41×33px），130 模式格子較小（34×28px），兩模式迴圈版面面積相同，切換不跳動（v1.7 新增）
- 排列方向：逆時針，左欄（去程）↓ → 下排 → 右欄（回程）↑ → 上排，Slot 1 在左上角緊鄰轉角二站
- 切換開關旁狀態列顯示：**上線 N 台｜雙擊格子輸入車號**（v1.13 移除水晶車廂台數顯示，回覆原始總數格式）

#### 自適應縮放（v1.1 新增）
`ResizeObserver` 持續監聽中央容器實際寬高，以 `scale = min(可用高/迴圈高, 可用寬/迴圈寬)` 等比縮放整個迴圈（最小 0.5），筆電自動縮小、桌機自動放大，無需捲動。

#### 方向箭頭（v1.2 改善，v1.12 修正）
- 中央欄左右各有 ↓（藍色，去程）與 ↑（橘色，回程）大字箭頭
- 上排（← ）與下排（→）各有橘紅色方向箭頭，位置依目前模式動態計算上下排中間格，108 與 130 模式均正確顯示（v1.12 修正：原本 108 模式 ← 箭頭因格位編號超出範圍而消失）

#### 拖曳排班
- 從儲車區直接拖曳車廂至正線任意格
- 拖曳至已有車廂的格子時，原車廂自動歸還轉角二站（v1.4 修正，不再產生幽靈車廂）
- 拖曳至迴圈中央大面積自動插入第一個空格

#### 雙擊格子輸入車號（Admin 限定）
雙擊任意格子後輸入車號：
- 清空後車廂移回轉角二站
- 車號不存在或已在正線其他格時顯示警告 Modal（v1.4 新增驗證）
- 同時更新 `main_line.positions` 與 `cars.location`，不產生重影（v1.4 修正）

#### 108 → 130 切換（v1.9 新增，v1.10 公式修正）
切換時自動依固定公式重排車廂位置：
- **第 1–65 格**：原有車廂不動
- **第 66–87 格**：自動空出（22 個空格，供插入新車）
- **第 88–130 格**：原第 66–108 格的車廂整體後移 22 格

無論原本 108 格是否滿載皆套用此公式，空格跳過不計入。

#### 130 → 108 切換（v1.7，v1.10 改善）
- 線上車 **≤ 108 台**（含 66–87 空格未補滿的情況）：壓縮空格後直接切換，不彈對話框，車廂順序完整保留（v1.10 修正：原本會誤送車廂至儲車區）
- 線上車 **> 108 台**：彈框顯示目前台數與超出台數，提供三個選項：
  - **確認抽出**：輸入起始車號，連續送回超出的 N 台（v1.10 改為動態台數，不再固定 22 台）
  - **略過抽車，直接切換**：位置最後的 N 台自動歸還轉角二站
  - **取消**
- 所有操作含 optimistic update，畫面即時反映（v1.1 修正）
- 抽車使用批次 API（v1.1 改善，原為逐一更新）

### 車廂操作（右鍵選單）

在任意車廂標籤上按右鍵可開啟選單：

| 選項 | 說明 |
|------|------|
| ← 移至轉角二站 | 一鍵移回，同時清除原格位；已在轉角二站時停用（v1.1 改善） |
| ★ 設為基準車 / 取消 | 基準車顯示紅色 ★ 加白色光暈，一次只能一台（v1.4 改善顏色）|
| 狀態切換 | 可用 ✅ / 不可用 🔴 / 管控 🟠 / 其他 🟢 / 報廢（含 optimistic update，v1.1 修正即時反應）|

### 車廂診斷（🔍 診斷）（Admin 限定）

點 🔍 診斷按鈕，自動掃描（直接查 Supabase，不依賴本地 state，v1.1 改善）：

| 掃描項目 | 說明 |
|----------|------|
| 各區車廂數量統計 | 正線、轉角二站、貓空站、自定義區、週排程、未分配 |
| 合計驗證 | 是否達到 151 台（1–147 + M1 + M2 + 雙握 + 洞）|

| 重複出現（duplicate） | 同一車號出現在多個格位（v1.1 新增修復邏輯）|

**一鍵修復**：異常車廂批次移回轉角二站，幽靈格位清除。

## 資料庫 Schema 補充

基本表結構見 `supabase/schema.sql`。以下為後續新增的欄位，需在 Supabase SQL Editor 手動執行：

```sql
-- v1.2：佈告欄
CREATE TABLE bulletin_board (
  id integer PRIMARY KEY DEFAULT 1,
  title text NOT NULL DEFAULT '佈告欄',
  date text NOT NULL DEFAULT '',
  content text NOT NULL DEFAULT '',
  updated_at timestamptz NOT NULL DEFAULT now()
);
INSERT INTO bulletin_board (id) VALUES (1);

-- v1.3：貓空站維修車活動日
ALTER TABLE bulletin_board
  ADD COLUMN IF NOT EXISTS maintenance_notes text NOT NULL DEFAULT '';

-- v1.4：車廂備註
ALTER TABLE cars ADD COLUMN IF NOT EXISTS notes text;
```

RLS 設定：
- `bulletin_board`：所有人 SELECT，登入用戶 UPDATE
- `cars.notes`：同 `cars` 資料表現有 RLS

## 系統轉交說明

本節說明如何將此系統完整移交給其他維護單位（如公司數發部）。

### 轉交原則

採「**交程式碼，對方重建基礎設施**」方式，雙方各自持有獨立帳號，原開發者的雲端服務於移交完成後可直接刪除。

### 需移交的內容

| 項目 | 說明 |
|------|------|
| 程式碼 | `maokong-dispatch/` 整包資料夾（壓縮或 Git repo） |
| 資料庫建表腳本 | `supabase/schema.sql`、`supabase/seed.sql` |
| 追加 SQL | README「資料庫 Schema 補充」章節的 ALTER TABLE 指令 |
| 本文件 | README.md 或本使用說明 docx |

> **不需要**移交：任何帳號密碼、.env 檔、Supabase/Vercel 帳號存取權。

### 移交步驟（接收方操作）

**Step 1 — 建立 Supabase 專案**
1. 至 [supabase.com](https://supabase.com) 申請帳號，新建 Project
2. 在 SQL Editor 依序執行：`schema.sql` → `seed.sql` → 追加 SQL（共三段 ALTER TABLE）
3. 至 Project Settings → API，記下 `SUPABASE_URL` 與兩組 Key

**Step 2 — 部署至 Vercel**
1. 至 [vercel.com](https://vercel.com) 申請帳號
2. 匯入程式碼（GitHub 或直接上傳），建立新 Project
3. 在 Vercel Project Settings → Environment Variables 填入：
   ```
   NEXT_PUBLIC_SUPABASE_URL=（Step 1 取得）
   NEXT_PUBLIC_SUPABASE_ANON_KEY=（Step 1 取得）
   ```
