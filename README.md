# 貓空纜車調度系統

貓空纜車車廂即時調度管理工具。以 Next.js + Supabase 建置，支援多人即時同步、拖曳排班、維修標記等功能。

**線上網址：** https://maokong-dispatch.vercel.app

---

## 系統架構

| 層次 | 技術 |
|------|------|
| 前端框架 | Next.js 16 (App Router) |
| 資料庫 | Supabase (PostgreSQL + Realtime) |
| 部署 | Vercel |
| 樣式 | Tailwind CSS + shadcn/ui |
| 拖曳 | dnd-kit |

## 功能總覽

### 正線迴圈
- 支援 **108 車** 與 **130 車** 兩種模式切換
- 逆時針排列：左欄（去程）↓ → 下排 → 右欄（回程）↑ → 上排，Slot 1 在左上角緊鄰轉角二站
- 格子序號：空格顯示槽位編號（灰色），有車顯示彩色車廂標籤
- **拖曳**：從儲車區直接拖到正線任意格，或拖到迴圈中央大面積自動插入第一個空格
- **雙擊格子**：手動輸入車號，清空後車廂移回轉角二站
- **130 → 108 切換**：點「108 車」按鈕後輸入起始車號，自動抽出 22 台送回轉角二站

### 車廂操作（右鍵選單）
在任意車廂標籤上按右鍵可：
- **← 移至轉角二站**：一鍵移回，同時清除原格位（正線/測試區/週排程皆適用）
- **★ 設為基準車** / 取消（基準車顯示黃色 ★ 標記）
- **狀態切換**：可用 ✅ / 不可用 🔴 / 管控 🟠 / 其他 🟢

### 儲車區
- **轉角二站儲車區**（左側欄上方）：可收折，收折後仍可接受拖放；上限 40 台
- **貓空站儲車區**（左側欄下方）：緊接轉角二站下方，同樣可收折；上限 10 台
- 左側欄按 ◀ 收折以釋放正線顯示空間，按 ▶ 展開；收折狀態下兩區分上下段顯示車數，均可接受拖放

### 測試區（正線迴圈中央）
- 預設顯示 3 個測試區，點數字 0–6 控制顯示數量
- 每區 6 格，可拖入或點 + 輸入車號，雙擊修改
- 右鍵選單可一鍵移回轉角二站

### 週排程（正線迴圈中央）
- 週一至週五各 10 格
- 可拖入車廂或點 + 輸入

### 維修排程 A / B / C（正線迴圈中央）
- 三個維修單元橫排，各可自訂名稱
- 登錄後車廂狀態自動顯示紫色「有維修需求」
- 輸入車號後即時顯示，不需重整頁面

### 佈告欄（正線迴圈中央，維修排程右側，自動撐滿剩餘寬度）
- 供控制員記錄班次交接資訊，標題可自訂（預設「佈告欄」）
- 日期欄自由文字輸入（如「5/29 AM 班」）；交接事項多行 textarea（8 行）
- 打字後 600ms 自動存檔，多端 Realtime 即時同步
- Admin 可編輯，Guest 唯讀

### 貓空站維修車活動日（左側欄，貓空站儲車區下方）
- 多行記事欄，供控制員記錄維修車活動日期與相關備註
- 打字後 600ms 自動存檔，多端 Realtime 即時同步
- Admin 可編輯，Guest 唯讀

### 搜尋車號
TopBar 搜尋框輸入車號（支援 Enter 快速查詢），顯示該車目前所在區域與格位，並標示是否有維修需求。

### 班次快照
Admin 按「💾 儲存班次」輸入班次說明，系統記錄當下完整狀態（正線排列、各區車廂、維修排程、週排程）。

### 車廂診斷（🔍 診斷）
TopBar 「🔍 診斷」按鈕（Admin 限定），開啟後自動掃描：
- 各區車廂數量統計
- 合計是否達到 151 台（1–147 + M1 + M2 + 雙握 + 洞）
- 異常偵測：孤兒車（DB 說在某區但 slots 找不到）、幽靈車（slots 有但 DB 位置不符）、未分配車、重複出現
- **一鍵修復**：異常車廂批次移回轉角二站，幽靈格位清除

### 系統設定（⚙）
Admin 限定，包含：
- **帳號管理**：新增 / 刪除帳號、切換 admin / guest 角色
- **水晶車設定**：點選車號切換水晶車（黃色）
- **報廢車管理**：設定後強制封鎖上正線
- **狀態顏色**：自訂各狀態顏色（含雙握車、洞車的灰色預設）

## 開發歷程

### v1.1 — 2026-05-29　介面優化與資料一致性強化

本次更新為系統上線後第一輪全面性改善，涵蓋 UI 易用性提升、多項邏輯 Bug 修正、診斷系統強化，以及正線版面的自適應重構。

---

#### 一、搜尋車號加亮（CarTag + TopBar + store）

**改動前**：搜尋到車號後只在頂列顯示文字結果，使用者需自行在畫面上尋找目標車廂，無視覺引導。

**改動後**：
- 搜尋命中後，目標車廂標籤立即套用紅色閃爍外框（CSS keyframe 動畫，4 次脈衝），不論車廂位於正線、儲車區、測試區或週排程任何位置皆適用。
- 高亮持續顯示直到使用者清空搜尋輸入框，不自動消失，方便在忙碌畫面中持續追蹤目標。
- 技術實作：在全域 `AppContext`（`store.tsx`）新增 `highlightedCarId` 狀態，`TopBar` 搜尋成功時寫入，輸入框清空時歸零；`CarTag` 依此狀態條件套用 `car-highlight` CSS class。

---

#### 二、右鍵選單功能全面修正（store + CarTag）

**問題一：狀態切換（可用／不可用／管控／其他）無即時反應**

根本原因：`updateCarStatus` 只送 Supabase 更新，未做本地樂觀更新，依賴 Realtime 推送才能反映，若 Realtime 延遲則畫面看似無反應。

修正：加入即時 `setCars` 更新，操作後畫面立即反映，Realtime 到來後再做一次確認同步。

**問題二：「設定基準車」無效、「取消基準車」完全沒有作用**

根本原因：`setReferencecar` 邏輯永遠執行「設定」路徑（`is_reference: id === carId`），不論當前是否已為基準車，取消情境從未被處理。

修正：改為由 `CarTag` 傳入 `car.is_reference` 當前狀態，`setReferencecar` 依此判斷：
- 當前已是基準車 → 清除所有 `is_reference`（取消）
- 當前不是基準車 → 先清除舊基準，再設定新基準

同時加入樂觀更新，操作後星號即時顯示或消失。

**問題三：「移至轉角二站」在車廂已位於轉角二站時仍可點擊**

邏輯矛盾修正：右鍵選單檢查 `car.location === 'zhuanjiaoer'`，若相符則將該選項反白停用（`disabled`、`cursor-not-allowed`），避免無意義操作。

---

#### 三、週排程重複車廂 Bug（DragHandler）

**問題描述**：將已在週排程的車廂拖曳至同一週排程的其他格位時，原格位未被清除，導致同一車廂在同一天中重複顯示。

**根本原因**：`executeMove` 函式為 async，在「清除來源格位」與「寫入目標格位」之間，使用的 `weeklySchedule` 是 React closure 的舊快照（stale closure），清除動作尚未反映到後續寫入所用的資料中，導致來源格位的車號被保留並再寫一次。

**修正方式**：在 `executeMove` 內追蹤一個 `latestWeeklySchedule` 局部變數，每次從週排程清除來源後立即更新此變數，後續寫入目標格位時改用此最新版本，確保來源清除結果被正確帶入。

---

#### 四、維修排程區與測試區換行顯示（MaintenancePanel + TestAreaPanel）

**改動前**：維修排程卡片的已登錄車號橫向無限延伸；測試區 6 個格子排成單排。

**改動後**：
- 維修排程：每張卡片改用 `grid-cols-3`，最多 3 台後自動換至第二排。
- 測試區：6 個格子改用 `grid-cols-3`，固定 3+3 兩排排列，視覺上更緊湊整齊。

---

#### 五、正線版面重構：長方形幾何 + 自適應縮放（MainLineLoop + MainLayout）

這是本次更新規模最大的改動，目的是解決在不同尺寸螢幕（筆電／桌機）下的顯示問題。

**問題描述**：原正線迴圈為固定尺寸，在小螢幕需上下捲動，在大螢幕右側留有大片空白。

**改動一：幾何比例調整（長方形迴圈）**

| 模式 | 修改前（上/左） | 修改後（上/左） | 說明 |
|------|----------------|----------------|------|
| 108 車 | 上下各 26、左右各 28 | 上下各 33、左右各 21 | 橫向延長，縱向縮短 |
| 130 車 | 上下各 32、左右各 33 | 上下各 40、左右各 25 | 同上，等比調整 |

調整後寬高比從約 1.1:1 改為約 1.8:1，與一般寬螢幕比例更吻合。

**改動二：雙軸自適應縮放**

- `MainLayout` 使用 `ResizeObserver` 持續監聽中央容器的實際寬高（`contentRect`）。
- `MainLineLoop` 接收 `availableHeight` 與 `availableWidth` 兩個參數，計算縮放比例：`scale = min(availableHeight / loopHeight, availableWidth / loopWidth)`，最小值 0.5。
- 整個迴圈（含中央所有面板）以 CSS `transform: scale(scale)` 等比縮放，外層容器同步調整為縮放後尺寸，確保佈局正確。
- 效果：筆電小螢幕自動縮小填滿視窗、桌機大螢幕自動放大利用空間，無需捲動。

**改動三：方向箭頭重新設計**

- 移除 SVG 文字箭頭（因被車廂格子 DOM 層疊蓋住導致不可見）。
- 改為在中央面板區域的左右兩側各配置一欄（寬 48px），分別顯示 42px 的藍色 ↓（去程）與橘色 ↑（回程），與車廂格子完全隔離，確保永遠可見。
- 同時移除中央原有的「去程／回程／轉角二站⇅貓空站」文字標示。

---

#### 六、車廂總覽診斷系統全面強化（DiagnosticsPanel）

診斷系統是本次改善幅度最大的後端邏輯模組，針對資料一致性檢查與修復做了多層次補強。

**問題一：重新掃描後異常重複出現**

根本原因：`handleScan` 與 `handleOpen` 使用 React 本地 state（`cars`、`mainLine` 等）執行掃描。修復完成後 Supabase Realtime 需要一段時間才能把更新推回本地 state，在這段空窗期點「重新掃描」拿到的是修復前的舊資料，因此異常重複出現。

修正：掃描邏輯全面改為直接向 Supabase 發出 SELECT 查詢取得最新資料，不依賴 React state。修復時的幽靈格位清除也同步改為先從 DB 取最新 `positions[]` 再操作，避免使用過時快照。

**問題二：`duplicate`（重複車號）異常無法被修復**

根本原因：`handleFix` 只處理 `orphan` 與 `ghost_main` 類型，`duplicate` 被偵測到後從未進入修復邏輯，每次修復後重新掃描都仍顯示相同異常。

修正：新增 `duplicate` 修復邏輯——從 DB 撈最新資料，對每台重複車廂跨正線、測試區、週排程全面掃描，保留第一個出現的格位，其餘一律清 null。

**問題三：週排程幽靈（ghost_weekly）與測試區幽靈（ghost_test）未被偵測**

這兩種異常指的是：slot 陣列中存有車號，但該車廂的 `location` 欄位已指向其他區域（例如車廂移走後 slot 未清除）。舊版診斷只偵測正線幽靈（`ghost_main`），週排程與測試區的幽靈資料會靜默存在、無法被發現。

修正：
- 新增 `ghost_weekly`、`ghost_test` 兩種 issue type。
- `runScan` 加入對應偵測邏輯：遍歷所有週排程格位與測試區格位，若車號存在但 `cars[id].location` 不符，標記為幽靈異常。
- `handleFix` 加入對應清除邏輯，直接將幽靈 slot 設為 null。

**問題四：CarTag「移至轉角二站」只清除第一個出現點**

根本原因：`handleMoveToStorage` 使用 `indexOf` 尋找車號後立即 `break`，遇到同一車號重複出現時只清第一格，其餘殘留。

修正：改用 `.map(s => s === carId ? null : s)` 對整個 day 的 slots 全面替換，並移除 `break`，確保所有天、所有格的重複出現全部清除。

**資料直接修復**：v1.1 部署時發現週一排程中殘留有車號 4 的幽靈資料（`location` 已為 `zhuanjiaoer` 但 slot 未清除），透過 Node.js 腳本直接操作 Supabase REST API 完成清除，不需停機或人工 SQL 介入。

#### 七、中央面板排列順序調整（MainLineLoop）

**改動前**：面板由左至右順序為 貓空站儲車區 → 週排程 → 維修排程。

**改動後**：調整為 週排程 → 維修排程 → 貓空站儲車區，與實際操作優先順序一致——排班工具（週排程、維修排程）靠近左側去程箭頭方便第一眼檢視，貓空站儲車區移至右側靠近回程箭頭，符合纜車路線方向的空間直覺。

#### 八、130 → 108 切換功能全面修正（store）

**問題描述**：原切換功能雖邏輯正確，但有三個實作缺陷影響實際使用體驗。

**問題一：畫面不即時反映（無 optimistic update）**

根本原因：`extractCarsFrom130To108` 只送 Supabase 更新，完全依賴 Realtime 推送才能更新畫面，操作後要等數秒才有視覺反饋，感覺像沒反應。

修正：操作確認後立即同步更新本地 `mainLine`（切回 108 模式、重整 positions）與 `cars`（抽出車廂 location 改為 `zhuanjiaoer`），畫面瞬間反映，DB 在背景同步。

**問題二：22 台車逐一更新 DB（效能差）**

根本原因：抽出的車廂以 `for...of` 逐一呼叫 `supabase.update().eq('id', cid)`，最多需要 22 次循序 API 回應，切換過程明顯緩慢。

修正：改用 `supabase.update().in('id', extractedIds)` 一次批次更新全部抽出車廂，並與正線 mode/positions 更新以 `Promise.all` 並行發送，大幅縮短等待時間。

**問題三：計算邏輯為「22 個格子」而非「22 台列車」**

原本行為：以固定 `for` 迴圈跑 22 次，每次對應一個格子位置——有車則收，空格則跳過但仍消耗計數，導致正線格子未填滿時實際抽出列車數少於 22 台。

修正後行為（方案 B）：改用 `while` 迴圈，只有確實收到一台列車才計數一次，遇到空格自動跳過繼續尋找，直到確實收滿 22 台實際列車為止。若正線總車數不足 22 台，則收完現有列車後安全停止（以總格數為上限，避免無限迴圈）。

### v1.2 — 2026-05-29　車廂擴充、佈告欄、介面微調

---

#### 一、新增雙握車與洞車兩種固定特殊車廂

**背景**：實務運作中有兩台特殊設備型列車——雙握車（供特殊作業）及洞車（供隧道作業），需在系統內被追蹤調度，但各僅一台，無需像水晶車一樣設定多台切換。

**做法**：仿照 M1、M2 的模式，直接以固定 ID 插入 `cars` 表：

| 車號 ID | 車型（type） | 預設顏色 |
|---------|------------|---------|
| 雙握 | shuangwo | 灰色 |
| 洞 | dong | 灰色 |

#### 二、水晶車顏色設定修復（store + Supabase 相容性）

**問題描述**：水晶車在設定頁調整顏色後，畫面上未反映新顏色。

**根本原因**：`loadAllData` 原本以 `setStatusColors(colors)` 直接取代整個顏色 state。若 Supabase `status_colors` 資料表缺少 `available_crystal` 欄位（較早建立的資料庫版本），`colors` 物件就不含此 key，整個 state 被覆蓋後 `available_crystal` 變為 `undefined`，`useCarColor` 拿到 undefined 使 CSS backgroundColor 失效。

**修正**：`loadAllData` 與 Realtime 訂閱改為 merge 更新：

```ts
const validColors = Object.fromEntries(
  Object.entries(rawColors).filter(([, v]) => v != null)
)
setStatusColors(prev => ({ ...prev, ...validColors } as StatusColors))
```

只覆蓋 DB 中有值的欄位，其餘保留程式預設值，確保向後相容。

同步修正 `CrystalTab` 的儲存邏輯：原本儲存時執行 `.neq('type', 'maintenance_vehicle')`（將所有非維修車重置為 regular），改為只重置同類型 `.eq('type', 'crystal')`，避免新增其他特殊車型後互相覆蓋。

#### 五、正線車號字體加大

**改動**：正線迴圈槽位（compact 模式）的車號字型從 `text-[10px]`（10px）→ `text-xs`（12px）→ `text-sm`（14px），儲車區標籤（non-compact）維持 `text-xs`（12px）不變。

**原因維持 non-compact 在 12px**：左側欄寬度 208px，實際可用寬約 176px。全形中文字元（如「雙握」）在 `text-sm`（14px）下寬度 ≈ 44px，超過 `min-w-[2.5rem]`（40px），flex-wrap 換行計算錯位，導致「洞」被推到下一排而前排留有空位。改回 12px 後「雙握」= 40px，4 個一排整齊對齊。

#### 六、正線方向箭頭重新設計

**問題一（樣式）**：舊方案以 `← ← ←` / `→ → →` 文字貼紙配半透明白底，與中央欄現有 ↓↑ 大字風格不一致。

**問題二（位置）**：舊方案的箭頭覆蓋在上排與下排的車槽上（`top: 0` / `top: loopHeight-SH`），影響車號觀察與操作。

**最終方案**：

1. 移除覆蓋車槽的舊箭頭
2. 動態計算特定槽位的水平座標，將箭頭精確定位於正線中央區內側：

| 箭頭 | 對齊槽位 | 位置 | 顏色 | 說明 |
|------|---------|------|------|------|
| ← | 112 號格正下方 | `top: RH + 4`（中央區頂端） | 橘色 | 上排回程方向；108 模式無 slot 112 時自動隱藏 |
| → | 45 號格正上方 | `bottom: RH + 4`（中央區底端） | 藍色 | 下排去程方向；108/130 兩模式皆顯示 |

座標計算函式 `slotCenterX(slotNum)` 依目前模式的 segment 設定（`left/bottom/right/top`）動態換算，切換 108/130 模式時位置自動更新。

箭頭以 `position: absolute`、`zIndex: 9`、`pointerEvents: none` 掛在迴圈外層容器最末，確保渲染在中央面板上方且不干擾拖曳操作。
